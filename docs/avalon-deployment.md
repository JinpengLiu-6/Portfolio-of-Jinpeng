# 阿瓦隆：Vercel 上线说明

简历首页继续由现有 Vite 构建生成；游戏入口为 `https://www.jpliu.work/avalon/`，接口为 `/api/avalon/{health,create,join,state,action}`。阿里云 DNS 无需新增记录。

## 首次配置数据库（一次即可）

1. 打开 Vercel 项目 `portfolio-of-jinpeng` 的 **Storage**，创建或连接 **Upstash Redis** 数据库。也可在 Upstash 控制台创建，再手动填写环境变量。
2. 将数据库关联到本项目的 **Production** 环境。开发/预览可单独关联；应用默认使用不同键前缀，不与正式房间混用。
3. 确认 Vercel 项目环境变量包含以下两个值（使用写入 Token）：

   - `UPSTASH_REDIS_REST_URL`
   - `UPSTASH_REDIS_REST_TOKEN`

   如果集成提供的是 `KV_REST_API_URL` 与 `KV_REST_API_TOKEN`，本项目也支持。
4. 重新部署 `main` 的最新提交。环境变量更改需要新部署才能生效。
5. 打开 `/api/avalon/health`，应得到 `{"ok":true}`。再进入 `/avalon/`，页面应显示「联机服务已就绪」。

数据库凭据只配置在 Vercel 环境变量中，不要提交进 GitHub，也不要使用 `VITE_` 前缀。`.env.example` 仅含占位符。套餐费用、额度和地域以创建时页面为准；不要在未确认的情况下选择付费选项。

没有配置数据库时，简历和游戏页面仍能加载，游戏接口明确返回 503，页面提示联机服务未配置。线上不会悄悄退回本地文件或内存房间，也不会声称已联机。

## 发布

该仓库已由用户关联 Vercel 的 `main` 分支。正常推送到 `main` 会触发生产部署，构建命令 `npm run build`，输出 `dist`，Node.js 22。`vercel.json` 仅添加游戏相关路径和安全响应头，没有覆盖简历首页路由。

仓库原有 GitHub Pages workflow 保留为手动触发；该仓库未启用 Pages，自动发布会返回 404，所以不再随 main 推送自动运行。Pages 只能部署静态页面，不能运行本游戏接口；真正联机请使用 Vercel 自定义域名。

## 本地开发

```sh
npm ci
npm run dev:avalon
```

- 简历：`http://localhost:5174/`
- 游戏：`http://localhost:5174/avalon/`
- 本地模式的数据位于 `.avalon-local/rooms.json`（已忽略，不会提交），仅供本机开发。
- `npm run dev` 保留原简历开发方式，不提供游戏接口。

使用真实开发 Redis 时，在本机 shell 设置服务端环境变量，再运行：

```sh
node scripts/avalon-dev.mjs --cloud
```

不要把正式生产数据库的键前缀用于本地测试。

## 存储与并发设计

- 每个房间是 Redis 中的私密 JSON 文档，动作刷新 7 天过期时间。
- 通过 Lua 比较并交换提交更新；并发失败会重新读取并重新验证权限与阶段，防止覆盖他人的投票、出牌或加入操作。
- 角色权限、投票判定、刺杀目标限制全部留在服务端。
- 结算后只保留票数汇总，前端拿不到个人投票记录。
- 截止时间存在 Redis；每次经过身份验证的同步/操作请求检查到期并原子推进。无需常驻进程或 `setInterval`；所有人离线时不持续运行，回来后按持久化期限恢复。未提交的投票和任务牌绝不自动代填。
- 客户端前台每 2 秒同步。身份响应明确禁止浏览器/CDN缓存；后台停止轮询。
- Presence 独立保存，不因心跳增加游戏版本或让投票失效。
- 房间码、角色、座位凭据、环境变量均不写入请求日志。

## 你们的自定义规则

开局取北京时间分钟个位决定队长（0 对应末位，超出人数循环），否决后顺位轮换；同一任务连续否决两次后，第三次组队免投票发车。任务结束后队长顺位轮换。全程仅公开汇总票数。

支持 5–10 人自动配角。派西维尔仅看见两位相同标记的候选人，刺客不能选择莫甘娜或其他已知同伴。7 人及以上第四任务需两张失败牌。大厅设置保存两种推进方式：房主手动或可调倒计时。

## 验证

```sh
npm test
npm run build
```

常规测试覆盖规则和独立函数实例的共享状态。真实 Redis 集成测试需要本机 Redis 的二进制目录（包含 `redis-server`、`redis-cli`）：

```sh
REDIS_TEST_BIN=/path/to/redis/bin npm test
```

真实 Redis 测试使用临时本地实例和 REST 适配层，执行实际 Lua，而非模拟原子更新。测试实例不接触云端数据，结束后关闭。

2026-11-20：44 项测试全部通过，包括真实 Redis 下 5、6、7、8 人的两种模式、同时投票、任务牌、第三队直接发车、刺杀拦截、冷启动读取、过期房间不能被旧请求复活。简历构建、手机子路径创建房间和简历首页展示已检查。线上是否已关联数据库，以 `/api/avalon/health` 的实测结果为准。
